# Core Architectural Principles

**Agent-Swarm** is a generalized, highly governed multi-agent framework designed to take ideas from planning to production. 

In essence, this is not a "chat bot that codes." It is a **deterministic factory floor for non-deterministic workers**, utilizing strict software engineering principles (contracts, interfaces, isolation, and state machines) to safely harness the chaos of Large Language Models.

## The Role of Prompt Engineering vs. Structural Guarantees
Many multi-agent frameworks attempt to solve architectural failures (e.g., infinite loops, invalid JSON, or semantic collisions) by relying on *prompt engineering*—adding sentences to the system prompt like *"Do not loop infinitely"* or *"Ensure your JSON is valid"*. This treats the LLM like a human and inevitably fails when context rot sets in.

This framework assumes the LLM **will** eventually hallucinate or fail. Therefore, responsibilities are strictly divided:
*   **Prompt Engineering is the Gas Pedal:** We use prompts to give agents deep context, specialized personas, and clear task direction to maximize their creative and analytical output.
*   **Structural Guarantees are the Brakes:** We do not prompt-engineer our way out of failure. We enforce safety mechanically. Instead of prompting an agent not to loop, we build a hard `max_retries` counter. Instead of prompting for valid JSON, we pipe output through a strict Pydantic v2 validator. We revoke the LLM's authority over the safety and state of the system.

The architecture is built upon four foundational pillars:

## 1. The Core vs. Adapter Boundary
The system is cleanly bifurcated into two independent layers:
*   **The Universal Core:** The orchestration engine. It handles state machines, phase transitions, budget enforcement, intent routing, and crash recovery. The Core is entirely domain-agnostic—it simply routes structured data.
*   **The Adapters:** The domain-specific implementations. The SDLC (Software Development Life Cycle) is merely one of these adapters, operating alongside others like Personal Optimization and Team Optimization. Adapters provide the concrete vocabulary (like specific Git or Web intents) and define the `GovernancePolicy` and `RepoDeclaration` that the Core enforces.

## 2. Execution Isolation & Shared Intents
Instead of having multiple agents stumbling over each other in a shared repository, execution is strictly isolated.
*   **Disjoint Worktrees:** Agents operate in isolated workspaces.
*   **The Intent System:** If an agent needs to mutate shared state, it cannot do so directly. It must construct a structured "Intent" (e.g., `AddRoute`, `RenameExport`).
*   **Normalization & Validation:** That intent is passed back to the Core, scrubbed of LLM hallucinations by a two-pass normalization layer, strictly validated against a Pydantic schema (with `extra="forbid"`), and then executed by a dedicated, deterministic Intent Service. This eliminates race conditions and semantic collisions.

## 3. Adversarial Validation (Maker vs. Checker)
The golden rule of this architecture is that **no agent validates its own work.**
The taxonomy of agents (Makers, Checkers, Providers, Orchestrators, Archivists) is structured so that every output generated by a Maker is immediately routed to a distinct Checker agent. This adversarial setup forces structural accountability and prevents agents from self-approving flawed logic.

## 4. Deterministic Guardrails
Strict mechanical limits are enforced to prevent runaway LLM execution:
*   **Budget & Escalation Ladders:** Strict retry ceilings (e.g., `max_retries`) and cost budgets exist. If a loop cannot close, it escalates up the ladder, ultimately hitting a Human Gate rather than burning tokens infinitely.
*   **Calibration & Measurement:** Every agent's success/failure rate is tracked in a Verdict Ledger. Agents must prove themselves in "Shadow Mode" before being promoted to live execution.
*   **Phase Gates:** Work moves through a rigid pipeline (e.g., Design → Build → Review). An agent cannot proceed until the explicit criteria for the current gate are satisfied.
